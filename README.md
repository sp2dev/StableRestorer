# StableRestorer

把 **osu!lazer** 的本地数据迁移回 **osu!stable** 的目录布局：

| 内容 | lazer 里的来源 | 写回 stable 的位置 |
| --- | --- | --- |
| 谱面 | `BeatmapSetInfo` + `files/` 哈希文件库 | `Songs/` |
| 皮肤 | `Skin`（跳过随游戏附带的） | `Skins/` |
| 本地回放 | `Score.Files`（`.osr`） | `Replays/` |

osu!lazer 把每个文件按 SHA-256 哈希重命名后存进 `files/` 里，只靠数据库记住"这个哈希原来叫什么名字"。
本工具读这份数据库（`client.realm`），把文件**按原文件名**放回 stable 的布局：

- 默认用**硬链接**，所以不额外占用磁盘空间（同一分区时；跨分区会自动改为复制并提前警告）；
- osu!lazer 的数据只会被**读取**，不会被修改或删除；
- 目标是 stable 里**已有**的谱面集/皮肤时，按 ID 认出来、复用原文件夹并补上缺的文件，不产生重复。

---

## 快速开始

解压发布包，双击 `stablerestorer.exe`（或运行 `stablerestorer`），会进入交互模式：

```text
============================================================
  StableRestorer 1.0.0
  把 osu!lazer 的曲库、皮肤与本地回放迁移到 osu!stable
============================================================

已载入上次使用的设置。

── 当前配置 ──────────────────────────────────
  osu!lazer 目录  ：<自动探测>
  osu!stable 目录 ：<自动探测>
  谱面写到        ：<stable 目录>\Songs
  皮肤写到        ：<stable 目录>\Skins
  回放写到        ：<stable 目录>\Replays
  迁移内容        ：谱面、皮肤、回放
  文件方式        ：硬链接（同一分区时不额外占用空间）
  未提交谱面      ：不导入（没有 online ID 的谱面）
  复用已有文件夹  ：是（按 set id 匹配，避免重复谱面）
  校验 SHA-256    ：是
  覆盖同名文件    ：否（内容不同时跳过并记录）

请选择操作：
  1) 体检          统计能迁移什么 + 检查目标目录与硬链接（不写任何文件）
  2) 开始迁移      真正创建文件
  3) 修改设置      选择要迁移的内容、指定目录与选项
  4) 帮助          显示完整命令行用法
  0) 退出

输入序号 [0]：
```

首次启动会**自动寻找**两边的安装位置（注册表、常见安装路径、各磁盘根目录），找不到或找错了就在
`3) 修改设置` 里改。设置会记到 `stablerestorer.settings.json`（与 exe 同目录），下次不用再填。

**建议顺序**：先 `1) 体检` 确认一切就绪 → 再 `2) 开始迁移`。

### 命令行

```powershell
stablerestorer check   --lazer <lazer目录> --out <stable目录>
stablerestorer migrate --lazer <lazer目录> --out <stable目录>
```

只想要统计、不检查目标目录时（此时可以省略 `--out`）：

```powershell
stablerestorer check --lazer <lazer目录> --no-target-check
```

迁移时如果只想要其中几类：

```powershell
stablerestorer migrate --lazer D:\osulazer --out D:\osustb --only skins,replays
```

迁移过程会显示进度：

```text
  [██████████░░░░░░░░░░░░░░]  42% 正在迁移谱面（35666/84934 个文件）
```

## 参数

| 参数 | 说明 |
| --- | --- |
| `--lazer <dir>` | osu!lazer 数据目录（含 `client.realm` 与 `files/`），也可直接指向 `client.realm` |
| `--out <dir>` | 输出目录，在它下面创建 `Songs/`、`Skins/`、`Replays/`。想先验证时可指向独立目录 |
| `--stable <dir>` | 已有的 osu!stable 安装目录，用来识别已有文件夹（默认等于 `--out`） |
| `--only <列表>` | 只迁移指定内容：`songs` / `skins` / `replays` / `all`，默认 `all`。也支持 `--no-skins`、`--no-replays` 这种排除式 |
| `--no-target-check` | 体检时只统计，不检查目标目录（不需要 `--out`） |
| `--keep-unsubmitted` | 连未提交的谱面（没有 online ID）也导入。默认**不导入** |
| `--no-reuse-existing` | 不复用已有文件夹，一律按本工具的命名新建（默认复用） |
| `--mode hardlink\|copy` | 文件创建方式，默认 `hardlink`，失败自动回退复制 |
| `--overwrite` | 目标存在且内容不是同一份文件时替换它（默认跳过并记录） |
| `--no-verify-hash` | 跳过源文件 SHA-256 校验（更快，但少了完整性检查） |
| `--no-progress` | 关闭进度显示 |
| `--no-color` | 关闭彩色输出（输出被重定向或设置了 `NO_COLOR` 时也会自动关闭） |
| `--report <file>` | JSON 报告路径，默认 `<out>/stablerestorer-report.json` |
| `--schema-version <n>` | Realm 结构版本，默认自动探测（52、51、50 …） |
| `--verbose` / `--quiet` | 详细 / 仅摘要 |

子命令还有 `schemas`（排查数据库版本）。

**退出码**：`0` 正常，`1` 运行错误，`2` 参数错误，`3` 数据库结构不匹配，`4` 体检发现缺失源文件，
`5` 迁移过程中有失败记录，`6` 体检发现阻塞问题。

## 迁移规则（要点）

### 谱面

- **文件夹命名**遵循 osu!stable/osu!lazer 的既有规则：`Songs/{setId} {Artist} - {Title}`，
  非法字符替换为 `_`，过长时先截断 `Artist`。
- **识别用 set id，不用名字**。stable 文件夹名以谱面集 ID 开头，所以同一个谱面集即使两边名字不同
  （stable 里是 `feat`、游戏 metadata 里是 `feat.`），也会被认出来并复用原文件夹。
- **未提交谱面默认不导入**：判据是"没有 online ID"（从未提交到 osu!），这类谱面在 stable 里没有
  对应曲目，包括 osu!lazer 自带的那几个教程谱面。注意这与 `Protected` 标志不是一回事，
  实测两者并不完全重合。
- **故事板等子目录**会按原文件名结构保留。

### 皮肤

- 文件夹名用皮肤的显示名（`Skin.Name`），非法字符替换、过长截断。
- **跳过随游戏附带的皮肤**：它们在 lazer 里由代码定义、没有任何文件，无法成为 stable 皮肤。
- **复用已有文件夹**：stable 导入皮肤时会在名字后面补来源，例如 lazer 里叫 `X` 的皮肤在磁盘上
  可能是 `X (hobby)`。本工具会保守匹配（完全相同，或以 `X (` 开头）并复用那个文件夹，
  把缺的文件补进去而不是另建一份。

### 回放

- 文件名为 `{玩家} - {artist} - {title} [{难度}] ({yyyy-MM-dd}) {规则}.osr`，
  与 osu!stable 自己写的格式一致。
- 规则后缀按 stable 的命名映射：`fruits` → `Catch`、`mania` → `OsuMania`，
  其余（含自定义规则集）用其短名。
- 同一玩家、同一谱面、同一天有多份回放时，追加 `-2`、`-3`… 区分（与 stable 行为一致）。
- 文件名过长时会**保留规则后缀和扩展名**，只截断前面的标题部分。
- 两类分数会被跳过：没有回放文件的、以及谱面信息已丢失的（没有元数据就无法构造稳定的文件名）。

### 通用

- 链接前会校验每个源文件的内容与它的哈希文件名是否一致，不一致就不写入。
- **只增不删**：唯一会删除的动作是 `--overwrite` 时替换目标文件本身。

## 体检（`check` / 菜单第 1 项）

一次搞定，**完全不写入**：不写文件，也不创建任何目录。内容包括

1. **统计**：谱面集 / 皮肤 / 回放各有多少、各类跳过多少（已删除、无文件、随游戏附带、
   未提交、缺回放文件、缺谱面信息）；
2. **曲库完整性**：逐个确认被引用的哈希在 `files/` 里都存在，并统计逻辑大小与
   硬链接/复制两种方式各自的空间代价；
3. **目标目录**：存在就实际试写一个探测文件；不存在就检查最近的上级目录能否写出文件
   （不会真的创建它）；
4. **硬链接可行性**：用卷序列号判断两边是否同一分区；
5. **逐个目标路径**：把每个文件都会走一遍路径安全检查，确认没有绝对路径、路径穿越或越界。

```text
── 体检结论 ──────────────────────────────────
  [通过] lazer 曲库可读：D:\osulazer\files
  [通过] 谱面目标目录已存在且可写：D:\osustb\Songs
  [通过] 皮肤目标目录已存在且可写：D:\osustb\Skins
  [通过] 回放目标目录已存在且可写：D:\osustb\Replays
  [通过] lazer 曲库与目标目录在同一分区，可以使用硬链接，几乎不额外占用空间。
  [通过] lazer 曲库里所有被引用的文件都存在（共 74666 个不同哈希）。
  [通过] 所有目标路径都通过了安全检查（没有绝对路径、路径穿越或越界）。
  [通过] 选中数据的逻辑大小 21.02 GiB；硬链接方式几乎不额外占用空间，复制方式约需 18.68 GiB。

体检通过：源数据与目标目录都可用，可以开始迁移。
```

走完整个映射需要十几秒（九万多个文件，只遍历一次），换来的是"体检通过 ⇒ 迁移不会再遇到
路径或来源问题"。任何一条变成 `[阻塞]` 时退出码为 `6`，不会开始迁移。

## 注意事项

1. **先备份** `client.realm`。本工具不会写它，但它一旦损坏就无法再推导文件名映射。
2. **硬链接的语义**：硬链接和 lazer 曲库里的文件是同一份数据。删掉任意一边不会丢数据，
   但**改一边会同时改两边**。需要两边完全独立就用 `--mode copy`。
3. **迁移前建议关闭 osu!lazer**。运行中也能读（共享方式打开），但如果它正在导入/删除谱面，
   数据库快照可能与磁盘不完全一致。
4. **交互模式会直接写进 stable 安装目录**。想稳妥就先体检，或把 stable 目录暂时指向测试目录。
5. **迁移后 stable 需要自己扫描**才会在选歌界面看到新谱面（切回 osu! 通常会自动扫描）。
   本工具不重建 `osu!.db` / `scores.db`，所以 stable 的**分数记录**不会凭空出现 ——
   回放文件只是放进 `Replays/` 供 osu! 重新关联。
6. **同一分区才能硬链接**。跨分区时工具会明确警告，并改用复制（会额外占用与曲库等量的空间）。
7. **验证过的数据库结构**：osu!lazer Realm schema **52**。换过 lazer 大版本后如果打不开数据库，
   用 `schemas` 子命令排查。

## 已知限制

- 不生成 `osu!.db` / `scores.db` / `collection.db`。
- 只增不删，没有回滚命令（因为用的是硬链接，手工删目录不会影响 lazer 数据）。
- 极端情况下会有几百个文件因为超出文件系统的硬链接上限（NTFS 每文件 1024）而改为复制；
  这些通常是被上千个谱面共享的小打击音，实测总占用在 MB 级。
- 少数历史遗留文件夹名（很老的无数字前缀命名）无法按 set id 识别，不会被合并。
- 皮肤复用是保守匹配：名字差异较大时（例如 lazer 里叫 `X skin remix`、磁盘上是 `X remix (作者)`）
  会新建一个文件夹而不是合并。
