# StableRestorer

把 **osu!lazer** 的曲库还原成 **osu!stable** 的 `Songs/` 目录结构。

osu!lazer 把每个文件按 SHA-256 哈希重命名后存在 `files/` 里，靠数据库记住"这个哈希原来叫什么名字"。
本工具读这份数据库，把文件**按原文件名**放回 stable 的 `Songs/` 布局：

- 默认用**硬链接**，所以不额外占用磁盘空间（同一分区时；跨分区会自动改为复制并提前警告）；
- osu!lazer 的数据只会被**读取**，不会被修改或删除；
- 目标是 stable 里**已有**的谱面集时，按 set id 认出来、复用原文件夹并补上缺的文件，不会产生重复谱面。

---

## 快速开始

解压发布包，双击 `stablerestorer.exe`，会进入交互模式：

```text
============================================================
  StableRestorer 1.0.0
  把 osu!lazer 的曲库还原成 osu!stable 的 Songs 目录
============================================================

──────────── 当前配置 ────────────
  osu!lazer 目录 : <自动探测>
  osu!stable目录 : <自动探测>
  还原到         : <stable 目录>\Songs
  文件方式       : 硬链接（同一分区时不额外占用空间）
  未提交谱面     : 不导入（没有 online ID 的谱面）
  复用已有文件夹 : 是（按 set id 匹配，避免重复谱面）
  校验 SHA-256   : 是
  覆盖同名文件   : 否（内容不同时跳过并记录）
──────────────────────────────────

请选择操作：
  1) 体检        只读取 lazer 数据库，报告能还原什么（不写任何文件）
  2) 演练        完整走一遍并校验，但不写文件，用来先看清单
  3) 开始还原    真正创建硬链接
  4) 修改设置    重新指定 lazer / stable 目录与选项
  5) 帮助        显示完整命令行用法
  0) 退出
```

首次启动会**自动寻找**两边的安装位置（注册表、常见安装路径、各磁盘根目录），找不到或找错了
就在 `4) 修改设置` 里改。设置会记到 `stablerestorer.settings.json`（与 exe 同目录），下次不用再填。

建议顺序：先 `1) 体检` 看文件齐不齐 → 再 `2) 演练` 看清单 → 最后 `3) 开始还原`。

### 命令行

```powershell
stablerestorer scan    --lazer <lazer数据目录>
stablerestorer restore --lazer <lazer数据目录> --out <stable目录> --stable <stable目录>
```

- `<lazer数据目录>`：含 `client.realm` 与 `files/` 的目录（osu!lazer 的安装/数据目录）；
- `<stable目录>`：osu!stable 的安装根目录，还原结果写进它的 `Songs/`。

## 参数

| 参数 | 说明 |
| --- | --- |
| `--lazer <dir>` | osu!lazer 数据目录，也可直接指向 `client.realm` |
| `--out <dir>` | 输出目录，在它下面创建 `Songs/`（想先验证时可指向一个独立目录） |
| `--stable <dir>` | 已有的 osu!stable 安装目录，用来按 set id 识别已有文件夹（默认等于 `--out`） |
| `--keep-unsubmitted` | 连未提交的谱面（没有 online ID）也导入。默认**不导入** |
| `--no-reuse-existing` | 不复用已有文件夹，一律按本工具的命名新建（默认复用） |
| `--mode hardlink\|copy` | 文件创建方式，默认 `hardlink`，失败自动回退复制 |
| `--dry-run` | 只做规划与校验，不写任何文件 |
| `--overwrite` | 目标存在且内容不是同一份文件时替换它（默认跳过并记录） |
| `--no-verify-hash` | 跳过源文件 SHA-256 校验（更快，但少了完整性检查） |
| `--report <file>` | JSON 报告路径，默认 `<out>/stablerestorer-report.json` |
| `--schema-version <n>` | Realm schema 版本，默认自动探测 |
| `--verbose` / `--quiet` | 详细 / 仅摘要 |

其它子命令：`scan`（只读体检）、`schemas`（排查数据库版本）、`osudb`（实验性，读 stable 的 `osu!.db`）。

退出码：`0` 正常，`1` 运行错误，`2` 参数错误，`3` 数据库版本不匹配，`4` 体检发现缺失源文件，
`5` 还原过程中有失败记录，`6` `osu!.db` 解析不通过。

## 还原规则（要点）

- **文件夹命名**遵循 osu!stable/osu!lazer 的既有规则：`{setId} {Artist} - {Title}`，
  非法字符替换为 `_`，过长时先截断 `Artist`。
- **识别用 set id，不用名字**。stable 文件夹名以谱面集 ID 开头，所以同一个谱面集即使两边名字
  不同（例如 stable 里是 `feat`、游戏 metadata 里是 `feat.`），也会被认出来并复用原文件夹。
- **未提交谱面默认不导入**：判据是"没有 online ID"（从未提交到 osu!），这类谱面在 stable 里
  没有对应曲目，包括 osu!lazer 自带的那几个教程谱面。
- **故事板等子目录**会按原文件名结构保留。
- 链接前会校验每个源文件的内容与它的哈希文件名是否一致，不一致就不写入。

## 注意事项

1. **先备份** `client.realm`。本工具不会写它，但它一旦损坏就无法再推导文件名映射。
2. **硬链接的语义**：硬链接和 lazer 曲库里的文件是同一份数据。删掉任意一边不会丢数据，
   但**改一边会同时改两边**。需要两边完全独立就用 `--mode copy`。
3. **还原前建议关闭 osu!lazer**。运行中也能读（共享方式打开），但如果它正在导入/删除谱面，
   数据库快照可能与磁盘不完全一致。
4. **交互模式会直接写进 stable 安装目录**。想稳妥就先演练，或把 stable 目录暂时指向测试目录。
5. **还原后 stable 需要自己扫描**才会在选歌界面看到新谱面（切换回 osu! 通常会自动扫描）。
   本工具不重建 `osu!.db`。
6. **同一分区才能硬链接**。跨分区时工具会明确警告，并改用复制（会额外占用与曲库等量的空间）。
7. **稳定的数据依据**：只在 osu!lazer 数据库结构（schema）52 上验证过。换过 lazer 大版本后
   如果打不开数据库，用 `schemas` 子命令排查。

## 已知限制

- 只处理 `Songs`。皮肤、回放、`collection.db` 尚未实现。
- 不生成 `osu!.db`。
- 只增不删，没有回滚命令。
- 极端情况下会有几十个文件因为超出文件系统的硬链接上限而改为复制（通常只有几 MB）。
- 少数历史遗留文件夹名（很老的无数字前缀命名）无法按 set id 识别，不会被合并。
- `osudb` 子命令目前解析不通过，会明确报错并拒绝输出，而不是给出可能错误的结果。
